Simulation API And Outputs

For runs from forcing files with spin-up and outputs, use an Experiment (Running Experiments). This page describes the lower-level Simulation API underneath it, for forcing held in memory, step-by-step coupling to other models, and custom loops:

  1. build a SnowpackGrid
  2. build BESSIModel, PDDModel, or ITMModel (or build_model(:bessi, grid; ...))
  3. build SnowpackForcing (see its docstring below for the optional fields)
  4. build Simulation
  5. call run!

Simulation owns two model-state objects: sim.ref is the reference state and sim.now is the evolving state. Model structs are configuration-only. By default a Simulation runs the forcing once (years=1) on the CPU and writes no NetCDF; pass write_netcdf=true, netcdf_variables, output_dir and backend=:gpu to change this.

For coupling workflows, initialize an explicit stepper and update its forcing between steps:

integrator = init_integrator(sim)
step!(integrator)                 # one scheduled forcing step
step!(integrator, 10)             # ten scheduled forcing steps
integrator.sim.forcing.air_temperature .= 265.15
sync_forcing!(integrator)
step!(integrator, 1.0, true)      # one externally supplied 1-day step
result = finalize!(integrator)

run!(sim) is a wrapper over init_integrator, run!(integrator), and finalize!(integrator). set_active_mask!(integrator, mask) restricts stepping to a subset of columns, and yearly_step!(integrator) advances a BESSI simulation by one forcing year and returns the annual coupling fields (SMB and mean surface temperature).

BESSIModel resolves the layered mass and energy balance. Its defaults are the setup calibrated against MAR over Greenland for daily forcing (see Model State And Step Flow). The default diurnal substeps require latitude_deg in the forcing; set diurnal_shortwave_substeps=false when latitude is unavailable or the forcing is already sub-daily. PDDModel uses a bulk snow reservoir with configurable ddf_snow, ddf_ice, refreezing_fraction, temperature_sigma, H_snow_max, and pdd_method. The default pdd_method=:simple uses positive mean temperature; pdd_method=:pism applies the Calov-Greve expectation integral at every timestep.

ITMModel ports the Fortran insolation-temperature-melt scheme. It requires explicit latitude_deg, surface_height, ice_thickness (m), and annual_pdd (K day) in SnowpackForcing. q_sw_net, when supplied, is its insolation driver; otherwise ITM uses shortwave_down. As in the original ITM, this insolation is top-of-atmosphere radiation that the model attenuates with its elevation-dependent transmissivity; supplying surface shortwave (for example MAR SWD) attenuates it twice and strongly underestimates melt. It preserves the Fortran scheme's per-step mmWE day^-1 fields (smb, smbi, melt, runoff, refreezing) and cumulative mmWE fields.

Input Units

SnowpackForcing accepts either model-native fields or user-facing fields:

  • air_temperature, snowfall_rate, and rainfall_rate use native units (K, kg m^-2 s^-1, kg m^-2 s^-1).
  • air_temperature_c, snowfall_mm_day, and rainfall_mm_day are converted to native units.
  • shortwave_down is always W m^-2.
  • ice_thickness is metres and annual_pdd is K day; both are required by ITMModel.
  • scalar and time-vector forcing values are broadcast over columns.

load_forcing_file can select spatial columns directly with mask_name and mask_threshold. Selection depends only on that mask variable. Each field is read once straight into the selected columns; dimensions are recognised by the names given as x_name/y_name (or x/y) and a time dimension, and any other dimension (vertical level, sector) is read at its first index. read_forcing_columns exposes the same reader for additional variables.

A host whose climate supplies only monthly air temperature and precipitation can derive the rest with shortwave_down_from_transmissivity (shortwave from a per-domain direct transmissivity; the longwave cloud proxy then diagnoses its own cloudiness), wind_speed_from_geometry (wind from elevation and slope), temperature_variability_sigma and red_noise_monthly (daily temperature variability about a smooth series). Chion does not call them itself.

Outputs

Simulation(...; write_netcdf=false) skips NetCDF output. Use netcdf_variables to request a state field such as :thickness, :all, or :monthly.

For BESSIModel, :monthly writes monthly surface SMB (surface_smb: precipitation − runoff + vapour exchange), smb_ice, runoff, melt, refreezing and sublimation changes, plus albedo and the monthly mean surface energy balance (W m^-2, positive into the surface): shortwave_down, shortwave_net, longwave_down, longwave_net, sensible_heat_flux, latent_heat_flux and rain_heat_flux.

For PDDModel, :all writes snowpack_swe, smb_ice, runoff, and pdd_sum every forcing step. :monthly writes month-end snowpack SWE and monthly changes in the three cumulative fields. Monthly output for both models is buffered and written to NetCDF in chunks after stepping.

For ITMModel, :all writes its Fortran-compatible state and budget fields at every forcing step. :monthly writes month-end snapshots of those fields.

NetCDF outputs include an unlimited, CF-style t record coordinate in days since 1970-01-01 00:00:00, using the proleptic_gregorian calendar. Full-state output uses the forcing timestamps, while monthly output uses the timestamp of the last forcing record in each month. For simulations that repeat the forcing for multiple years, timestamps are advanced by one calendar year for each cycle. PDD smb_ice is ice-facing, consistent with BESSI: refrozen water and snow above H_snow_max are transferred to ice, while ice melt is negative SMB. Seasonal snow retained in snowpack_swe is not credited to the ice sheet.

NetCDF output requires a SnowpackGrid with spatial coordinates.

Use backend=:threads for the CPU and backend=:gpu with a functional CUDA environment. CUDA.jl is a weak dependency: using CUDA loads the GPU backend (the ChionCUDAExt package extension). Without it, backend=:gpu stops with an error that asks for using CUDA.

Host Forcing Helpers

These functions build forcing fields for runs without a regional climate model (for example, forcing from an ice-sheet model's climate). clear_sky_transmissivity needs the physical constants of a model, model.c:

model = BESSIModel(grid)
tau_cs = clear_sky_transmissivity(model.c, 2000.0, 300.0)   # height (m), TOA SW (W m⁻²)

PDDModel and ITMModel accept number_type like BESSIModel (number_type=Float32 for single precision).

Chion.SnowpackForcing — Type
SnowpackForcing(; dt_days, air_temperature_c, snowfall_mm_day, rainfall_mm_day,
                shortwave_down, time_values=nothing, ncol=nothing, kwargs...)

Time-varying atmospheric boundary conditions for a snowpack model, one value per column and forcing step. Fields are given as a matrix (ncol, ntime), a vector over time (one column, or the same for every column), or a scalar.

Required:

  • dt_days: length of each forcing step (days); its length sets ntime.
  • the air temperature and precipitation, either as air_temperature_c (°C), snowfall_mm_day, rainfall_mm_day (mm w.e. day⁻¹) or in model units as air_temperature (K), snowfall_rate, rainfall_rate (kg m⁻² s⁻¹).
  • shortwave_down (W m⁻²).

Optional (missing fields use the parameterisations of the model):

  • time_values: DateTime of each step (default: daily from 2001-01-01 12:00); sets the calendar years and the solar geometry.
  • latitude_deg, surface_height (m): needed by the diurnal substeps and the cloud-proxy longwave; surface_height also gives the barometric air_pressure when no pressure is supplied.
  • wind_speed (m s⁻¹, default 5), relative_humidity (fraction or %), air_pressure (Pa).
  • prescribed surface fluxes q_sw_net, q_lw_down, q_sh, q_lh (W m⁻²), prescribed_albedo (with albedo=:prescribed), prescribed_melt (kg m⁻² per step). Each has an optional has_* mask to prescribe it only for some columns or steps.
  • SEMIX albedo inputs cloud, coszm, dust_deposition, z_sur_std, prescribed_ice_albedo.
  • ice_thickness, annual_pdd: ITM inputs.

Chion.clear_sky_transmissivity — Function
clear_sky_transmissivity(c, height, toa)

Daily shortwave transmissivity of a clear sky (Konzelmann et al., 1994) at the surface height height (m) and daily-mean top-of-atmosphere shortwave toa (W m⁻²), τcs = min(1, τ₀ + τz z + τS ln(SWTOA / 300 W m⁻²)) with z in km, the reference of the cloud proxy's cloud fraction. A height that is not finite (no surface height) or negative counts as sea level; toa is floored at 50.0 W m⁻², as in the proxy.

source
Chion.shortwave_down_from_transmissivity — Function
shortwave_down_from_transmissivity(toa, height; trans0, trans_per_km)

Surface shortwave down (W m⁻²) from the top-of-atmosphere shortwave toa (W m⁻²) and the surface height height (m) with a per-domain direct transmissivity: SW↓ = SWTOA clamp(τ₀ + τkm max(z, 0)[km], 0, 1). A height that is not finite counts as sea level. The cloud proxy then diagnoses its own cloudiness from this SW↓.

Calibration (with Chion's TOA): MAR v3.14 1981-2010 over Greenland's ice gives τ₀ = 0.587, τkm = 0.052 km⁻¹ in summer; CERES gives τ₀ = 0.68, τkm = 0.041 km⁻¹ over Antarctica.

source
Chion.wind_speed_from_geometry — Function
wind_speed_from_geometry(z_srf, dx; u0, u_z=0, u_s=0, slope_length_km=50)

Wind speed (m s⁻¹) from the surface elevation z_srf (m) on a regular grid of spacing dx (m): U = u0 + uz max(z, 0)[km] + us |∇z|[m/km], at least 0. The slope is a centred difference over 2n cells, n = max(1, round(L/(2 dx))) for the baseline L = slope_length_km, so that it does not depend on the grid's resolution; one-sided over the cells available at the edges. u_s = 0 needs no dx.

Calibration: ERA5 1981-2010 summer 10-m wind over the ice gives Greenland 2.5 + 1.27 z[km], Antarctica 5.5 + 0.2 z[km] (u_s = 0).

source
Chion.temperature_variability_sigma — Function
temperature_variability_sigma(t_mon, T0; sigma0, slope, smin, smax)

Standard deviation (K) of the daily air temperature about a smooth (monthly-interpolated) daily series, from the monthly mean air temperature t_mon (K): σ = clamp(σ₀ + slope (Tmon − T₀), smin, smax). The daily temperature is then T = Tsmooth + σ ξ, with ξ from red_noise_monthly. σ falls with the monthly mean temperature and is lowest over melting surfaces (Seguinot and Rogozhina 2014, J. Glaciol. 60, 603).

Calibration: ERA5 1981-2010 over the Greenland and Antarctic ice gives σ = 2.0 − 0.14 (T_mon − T₀) in [2, 6] K.

source
Chion.red_noise_monthly — Function
red_noise_monthly(nday, dt_days, nday_mon, tau, seed)

One year of red noise ξ, a value per step of dt_days days (nday ÷ dt_days values): AR(1) with the lag-one correlation exp(−dt/τ), e-folding time tau (days; ERA5: 4-6 d), driven by standard normals; then its mean removed in every month of nday_mon days and the whole scaled to unit variance.

The normals come from a portable Park-Miller minimal standard generator, x ← 16807 x mod (2³¹ − 1) with x₀ = mod(|seed|, 2³¹ − 2) + 1, two uniforms per normal and the Box-Muller cosine branch, so a seed gives the same sequence as the Fortran chion's forcing_red_noise_monthly.

Chion.BESSIModel — Type
BESSIModel(grid; albedo=:dynamic, seb_scheme=:semix,
           turbulent_flux_scheme=:semix, densification=:bessi, ...)

Configuration for the layered BESSI snowpack model. Evolving state is stored in BESSIState and owned by Simulation.now. Turbulent sensible and latent heat use the SEMIX formulation by default; set turbulent_flux_scheme=:bessi to use the BESSI formulation. seb_scheme independently controls the remaining surface-energy-balance details and defaults to :semix for consistent graybody longwave exchange. Set seb_scheme=:bessi for the original BESSI formulation.

The defaults are the GrIS-calibrated setup for daily forcing: dynamic albedo, cloud-proxy longwave, a 5-layer thermal ice substrate, fine near-surface layers and up to 8 diurnal substeps with a 1 K air-temperature cycle.

Keywords:

  • schemes: albedo (:dynamic, :constant, :aging, :semix, :prescribed), seb_scheme, turbulent_flux_scheme (:semix, :bessi), longwave_scheme (:cloud_proxy, :graybody), densification (:bessi, :htessel), fresh_snow_density (:constant, :parameterized).
  • layers: Ntot=15, mass_max=500, mass_split=300, mass_min=100 (kg m⁻²), near_surface_layer_max_thicknesses_m=(0.02, 0.05, 0.10, 0.30), ice_substrate_layers=5, ice_substrate_top_thickness_m=0.05, density_init=300, temperature_init=273, refreezing_correction=1.
  • diurnal cycle: diurnal_shortwave_substeps=true, diurnal_shortwave_max_substeps=8, diurnal_shortwave_threshold=0, diurnal_shortwave_min_air_temperature_c=-8, diurnal_temperature_cycle=true, diurnal_temperature_amplitude_c=1, diurnal_temperature_amplitude_gradient_c_per_km=0, diurnal_temperature_amplitude_reference_height_m=0, diurnal_temperature_amplitude_max_c=1.
  • number_type=Float64 (Float32 for single precision, about 2× faster on GPUs).
  • any physical constant of SnowpackPhysicalConstants (e.g. alpha_dry, semix_sensible_exchange_factor, lw_night_cloud_fraction); see the Default Parameters page. The values in use are in model.c.

BESSIModel(forcing::Forcing; kwargs...) builds the model on the columns of a file-backed forcing.

Chion.PDDModel — Type
PDDModel(grid; ddf_snow=3.0, ddf_ice=8.0, refreezing_fraction=0.6,
         temperature_sigma=5.0, H_snow_max=5000.0, pdd_method=:simple,
         number_type=Float64)

Bulk positive-degree-day surface mass-balance model configuration. The model uses a capped one-layer snow reservoir: refrozen water and snow above H_snow_max become ice, while smb_ice records only ice-facing mass changes. Set pdd_method=:pism to use the Calov-Greve expectation integral for every timestep; :simple uses positive mean temperature directly. number_type sets the floating-point type of the parameters and state.

source
Chion.ITMModel — Type
ITMModel(grid; kwargs...)

Insolation-temperature-melt bulk surface-mass-balance model, ported from the Fortran fesmc/chion/smbpal implementation. ITM requires explicit surface_height, ice_thickness, annual_pdd, and latitude_deg fields in SnowpackForcing; q_sw_net is used as its insolation driver when supplied, otherwise shortwave_down is used.

Chion.Simulation — Type
Simulation(model; forcing, state=nothing, years=1, backend=:threads,
           write_netcdf=false, netcdf_variables, output_dir, name, ...)

Couple a model configuration with forcing, reference state, current state, and execution/output options. years repeats the forcing that many times. The keywords override the corresponding RunOptions fields; without them a Simulation runs the forcing once, on the CPU, without NetCDF output. sim.ref is a copy of the initial state and sim.now the evolving state.

Chion.load_forcing_file — Function
load_forcing_file(path; kwargs...) -> (grid, forcing)

Load a generic NetCDF forcing file into a SnowpackGrid and SnowpackForcing. Required variables default to x, y, time, TT, SF, RF, and SWD; optional turbulent/radiative flux fields and prescribed surface albedo are loaded when present and requested. If no explicit pressure field is requested, the static surface_height_name field is used to derive air pressure with the barometric formula. Set mask_name and mask_threshold to load only columns selected by a spatial mask variable.

source
Chion.read_forcing_columns — Function
read_forcing_columns(ds, name, rows, ntime, ny, nx; x_name="x", y_name="y")

Read the gridded variable name from the open dataset ds as a (length(rows), ntime) Float64 matrix in one pass. rows are flat column indices i + (j - 1) * nx. The x and y dimensions are found by the names x_name/y_name (or x/y) and the time dimension by name; any other dimension (vertical level, sector) is read at its first index only. Variables without recognisable x/y/time dimensions fall back to shape matching.
