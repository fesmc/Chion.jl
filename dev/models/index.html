Models And Coupling

For runs from forcing files with spin-up and outputs, see Running Simulations. This page describes the pieces underneath a Simulation, for forcing held in memory, step-by-step coupling to other models, GPUs and automatic differentiation:

  1. build a Grid: the columns, their optional x–y layout and the vertical Layering
  2. build the forcing: a file-backed Forcing or an in-memory SnowpackForcing (see its docstring below for the optional fields)
  3. build BESSIModel, PDDModel or ITMModel with its parameters (Params, PDDParams, ITMParams)
  4. wrap it in a Simulation and call run!, or step the model directly
julia> using Chion

julia> grid = Grid(2; layering = Layering(Ntot = 20));

julia> forcing = SnowpackForcing(dt_days = ones(3), ncol = 2, air_temperature_c = -5.0,
           snowfall_mm_day = 2.0, rainfall_mm_day = 0.0, shortwave_down = 100.0, latitude_deg = 70.0);

julia> model = BESSIModel(grid; forcing, params = Params(albedo_scheme = AgingAlbedo()));

julia> sim = Simulation(model; verbose = false);

julia> run!(sim);

julia> finished(sim), model.Ntot, size(model.mass)
(true, 20, (20, 2))

A model holds its grid, the prognostic state, a cache (diagnostics, scratch arrays and the active columns), the params and the forcing (the source and the loaded calendar year). Their fields are forwarded, so model.mass and model.Tsrf read the state, model.thickness the cache, model.alpha_dry and model.albedo_scheme the parameters, model.ncol and model.Ntot the grid, and model.year the loaded forcing year. A model knows nothing about time beyond the loaded forcing year; a Simulation advances it.

BESSIModel resolves the layered mass and energy balance. Its default parameters are the setup calibrated against MAR over Greenland for daily forcing (see Parameters). The default diurnal substeps require latitude_deg in the forcing; use Params(diurnal_cycle = NoDiurnalCycle()) when latitude is unavailable or the forcing is already sub-daily. PDDModel uses a bulk snow reservoir with the degree-day factors ddf_snow and ddf_ice, refreezing_fraction, temperature_sigma, H_snow_max and the method of PDDParams. The default method = SimplePDD() uses the positive mean temperature; method = PISMPDD() applies the Calov–Greve expectation integral at every timestep.

ITMModel ports the Fortran insolation–temperature–melt scheme. It requires explicit latitude_deg, surface_height, ice_thickness (m), and annual_pdd (K day) in SnowpackForcing. q_sw_net, when supplied, is its insolation driver; otherwise ITM uses shortwave_down. As in the original ITM, this insolation is top-of-atmosphere radiation that the model attenuates with its elevation-dependent transmissivity; supplying surface shortwave (for example MAR SWD) attenuates it twice and strongly underestimates melt. It preserves the Fortran scheme's per-step mmWE day^-1 fields (smb, smbi, melt, runoff, refreezing) and cumulative mmWE fields.

Number Type

NF sets the floating-point type of the grid, the parameters, the state and the forcing fields that the kernels read. The grid and the parameters must agree: Grid(n; NF = Float32) with Params(; NF = Float32), or BESSIModel(forcing; NF = Float32), which builds both. PDDModel and ITMModel take PDDParams(; NF) and ITMParams(; NF) in the same way.

Backends

A model lives on a KernelAbstractions backend: CPU() (multithreaded, the default) or, after using CUDA, CUDABackend(). CUDA.jl is a weak dependency: using CUDA loads the GPU backend (the ChionCUDAExt package extension).

using CUDA
model = BESSIModel(grid; forcing, backend = CUDABackend())
model = to_backend(model, CUDABackend())     # or move an existing model
state = cpu_state(model)                     # host copy of the state
set_state!(model, state)                     # copy a host state (e.g. a restart) back

ReactantBackend() (after using Reactant, CUDA, the ChionReactantExt extension) runs a BESSIModel through Reactant.jl and XLA: the column step is compiled once per integrate! call or forcing year and stepped from the host, and agrees with the CPU to roundoff (test/reactant/runtests.jl, its own environment). PDD and ITM models, resetting columns and device-side output accumulation are not available there.

Coupling

A Simulation can be advanced one forcing step or one year at a time, with the model's inputs changed in between:

sim = Simulation(model; years = 2000:2100)
time_step!(sim)                              # one forcing step (spin-up first, if any)
set_input!(sim, :surface_height, z_s)        # e.g. from an ice-sheet model, per column
set_active_mask!(sim, ice_mask)              # step only these columns
fields = yearly_step!(sim)                   # the next forcing year (must start at its first step)
fields.smb_ice_yearly                        # kg m⁻² per column; fields.mean_T_srf_K in K
run!(sim; years = 10)                        # ten more years

set_input! replaces a forcing field of the loaded year (after editing model.forcing.data in place, sync_forcing!(model) moves it to the kernels); set_active_mask! takes a column vector or a y–x matrix on the grid, and resets columns that become inactive to the initial state unless reset_newly_inactive = false. yearly_step! returns the annual coupling fields smb_ice_yearly and mean_T_srf_K, also as y–x matrices (*_grid) when the grid has spatial coordinates.

Without a Simulation, integrate!(model, steps) advances the model over the forcing steps steps of the loaded year, without output and without changing the year; update_forcing!(model, year) loads another year. integrate! is the entry point for automatic differentiation.

Automatic Differentiation

Columns are smooth functions of the parameters and the forcing between discrete events (layer split/merge, snow↔ice switches), so derivatives are pathwise slopes. Two paths are tested against finite differences (test/test_autodiff.jl):

  • ForwardDiff through a whole model: build it at a dual number type and give the parameter of interest a unit partial (using ForwardDiff loads ChionForwardDiffExt, which lets outputs and logs take the values of the duals):
using Chion, ForwardDiff
function melt(alpha_dry)
    NF = typeof(alpha_dry)
    model = BESSIModel(Grid(n; NF); forcing, params = Params(; NF, alpha_dry))
    integrate!(model, 1:365)
    return sum(model.state.melt)
end
ForwardDiff.derivative(melt, 0.81)          # kg m⁻² per unit albedo
  • Enzyme forward mode through column_step!, on the CPU and inside the GPU kernel (autodiff_deferred), with the state arrays as Duplicated arguments.

Scheme coefficients differentiate the same way (SemixTurbulentFluxes(sensible_exchange_factor = Dual(…))). Reverse mode is not available for the layered model.

Input Units

SnowpackForcing accepts either model-native fields or user-facing fields:

  • air_temperature, snowfall_rate, and rainfall_rate use native units (K, kg m^-2 s^-1, kg m^-2 s^-1).
  • air_temperature_c, snowfall_mm_day, and rainfall_mm_day are converted to native units.
  • shortwave_down is always W m^-2.
  • ice_thickness is metres and annual_pdd is K day; both are required by ITMModel.
  • scalar and time-vector forcing values are broadcast over columns.

A model takes a SnowpackForcing directly (it becomes a one-year Forcing). load_forcing_file can select spatial columns directly with mask_name and mask_threshold. Selection depends only on that mask variable. Each field is read once straight into the selected columns; dimensions are recognised by the names given as x_name/y_name (or x/y) and a time dimension, and any other dimension (vertical level, sector) is read at its first index. read_forcing_columns exposes the same reader for additional variables.

Host Forcing Helpers

A host whose climate supplies only monthly air temperature and precipitation can derive the rest with shortwave_down_from_transmissivity (shortwave from a per-domain direct transmissivity; the longwave cloud proxy then diagnoses its own cloudiness), wind_speed_from_geometry (wind from elevation and slope), temperature_variability_sigma and red_noise_monthly (daily temperature variability about a smooth series). Chion does not call them itself. clear_sky_transmissivity needs the parameters of a model, whose CloudProxyLongwave holds the coefficients:

tau_cs = clear_sky_transmissivity(model.params, 2000.0, 300.0)   # height (m), TOA SW (W m⁻²)

Chion.Grid — Type
struct Grid{NF, L<:Union{Nothing, SpatialLayout}}

The discretisation of a model: ncol independent columns, their optional x–y layout, and the vertical Layering of every column, at the floating-point type NF of the model.

Grid(ncol; NF = Float64, layering = Layering(), x, y, js, is, mask)
Grid(forcing::Forcing; NF = Float64, layering = Layering())

x, y, js, is (and optionally mask) give the SpatialLayout; without them the columns have no coordinates. Grid(forcing) takes the columns and layout of a file-backed forcing.

julia> grid = Grid(4; layering = Layering(Ntot = 20));

julia> grid.Ntot, grid.ncol
(20, 4)

Fields

  • ncol::Int64: number of columns

  • layout::Union{Nothing, SpatialLayout}: x–y positions of the columns, or nothing

  • layering::Layering{NF} where NF: vertical discretisation of every column

Chion.Layering — Type
struct Layering{NF<:Real}

Vertical discretisation of a column: up to Ntot snow and firn layers whose masses are kept between mass_min and mass_max (a layer above mass_max splits into mass_split and the rest), finer layers near the surface (near_surface_layer_max_thicknesses_m, the maximum thicknesses of the top four layers), and a thermal ice substrate of ice_substrate_layers layers below the firn whose thicknesses double downward from ice_substrate_top_thickness_m.

Fields

  • Ntot::Int64 = DEFAULT_NTOT: maximum number of snow and firn layers (default 15)

  • mass_max::Real = DEFAULT_MASS_MAX: mass above which a layer splits (kg m⁻², default 500)

  • mass_split::Real = DEFAULT_MASS_SPLIT: mass of the upper part of a split layer (kg m⁻², default 300)

  • mass_min::Real = DEFAULT_MASS_MIN: mass below which a layer merges with its neighbour (kg m⁻², default 100)

  • near_surface_layer_max_thicknesses_m::NTuple{4, NF} where NF<:Real = (0.02, 0.05, 0.1, 0.3): maximum thicknesses of the top four layers (m, default (0.02, 0.05, 0.10, 0.30))

  • ice_substrate_layers::Int64 = 5: number of ice-substrate layers below the firn (default 5; 0 for snow on land)

  • ice_substrate_top_thickness_m::Real = 0.05: thickness of the top ice-substrate layer (m, default 0.05)

Chion.BESSIModel — Type
mutable struct BESSIModel{G<:Grid, S<:BESSIState, C<:Chion.BESSICache, P<:Params, B<:BoundaryConditions, F<:Chion.AtmosphericForcing} <: Chion.AbstractSnowModel

The layered BESSI snowpack and firn model: a Grid, the BESSIState, the BESSICache, the Params and the AtmosphericForcing. Wrap it in a Simulation to run it.

BESSIModel(grid; forcing, params = Params(), boundary = BoundaryConditions(), backend = CPU(), state = nothing)

forcing is a Forcing or an in-memory SnowpackForcing; its first year is loaded. backend is a KernelAbstractions backend (CPU(), CUDABackend()) or its name (:threads, :gpu). state (a host BESSIState, e.g. a restart) replaces the initial state of params. Fields resolve through the model: model.mass (state), model.thickness (cache), model.alpha_dry (params), model.ncol, model.Ntot (grid), model.year (loaded forcing year).

julia> grid = Grid(2);

julia> forcing = SnowpackForcing(dt_days = ones(3), ncol = 2, air_temperature_c = -5.0, snowfall_mm_day = 2.0,
           rainfall_mm_day = 0.0, shortwave_down = 100.0, latitude_deg = 70.0);

julia> model = BESSIModel(grid; forcing, params = Params(albedo_scheme = ConstantAlbedo()));

julia> model.albedo_scheme, size(model.mass)
(ConstantAlbedo(), (15, 2))

Fields

  • grid::Grid: columns, layout and layering

  • state::BESSIState: prognostic arrays

  • params::Params: physical constants and schemes

  • boundary::BoundaryConditions: surface and bottom boundary conditions of the heat solve

Chion.SnowpackForcing — Type
SnowpackForcing(; dt_days, air_temperature_c, snowfall_mm_day, rainfall_mm_day,
                shortwave_down, time_values=nothing, ncol=nothing, kwargs...)

Time-varying atmospheric boundary conditions for a snowpack model, one value per column and forcing step. Fields are given as a matrix (ncol, ntime), a vector over time (one column, or the same for every column), or a scalar.

Required:

  • dt_days: length of each forcing step (days); its length sets ntime.
  • the air temperature and precipitation, either as air_temperature_c (°C), snowfall_mm_day, rainfall_mm_day (mm w.e. day⁻¹) or in model units as air_temperature (K), snowfall_rate, rainfall_rate (kg m⁻² s⁻¹).
  • shortwave_down (W m⁻²).

Optional (missing fields use the parameterisations of the model):

  • time_values: DateTime of each step (default: daily from 2001-01-01 12:00); sets the calendar years and the solar geometry.
  • latitude_deg, surface_height (m): needed by the diurnal substeps and the cloud-proxy longwave; surface_height also gives the barometric air_pressure when no pressure is supplied.
  • wind_speed (m s⁻¹, default 5), relative_humidity (fraction or %), air_pressure (Pa).
  • prescribed surface fluxes q_sw_net, q_lw_down, q_sh, q_lh (W m⁻²), prescribed_albedo (with albedo=:prescribed), prescribed_melt (kg m⁻² per step). Each has an optional has_* mask to prescribe it only for some columns or steps.
  • SEMIX albedo inputs cloud, coszm, dust_deposition, z_sur_std, prescribed_ice_albedo.
  • ice_thickness, annual_pdd: ITM inputs.

Chion.clear_sky_transmissivity — Function
clear_sky_transmissivity(params, height, toa)

Daily shortwave transmissivity of a clear sky (Konzelmann et al., 1994) at the surface height height (m) and daily-mean top-of-atmosphere shortwave toa (W m⁻²), τcs = min(1, τ₀ + τz z + τS ln(SWTOA / 300 W m⁻²)) with z in km, the reference of the cloud proxy's cloud fraction. A height that is not finite (no surface height) or negative counts as sea level; toa is floored at 50.0 W m⁻², as in the proxy.

source
Chion.shortwave_down_from_transmissivity — Function
shortwave_down_from_transmissivity(toa, height; trans0, trans_per_km)

Surface shortwave down (W m⁻²) from the top-of-atmosphere shortwave toa (W m⁻²) and the surface height height (m) with a per-domain direct transmissivity: SW↓ = SWTOA clamp(τ₀ + τkm max(z, 0)[km], 0, 1). A height that is not finite counts as sea level. The cloud proxy then diagnoses its own cloudiness from this SW↓.

Calibration (with Chion's TOA): MAR v3.14 1981-2010 over Greenland's ice gives τ₀ = 0.587, τkm = 0.052 km⁻¹ in summer; CERES gives τ₀ = 0.68, τkm = 0.041 km⁻¹ over Antarctica.

source
Chion.wind_speed_from_geometry — Function
wind_speed_from_geometry(z_srf, dx; u0, u_z=0, u_s=0, slope_length_km=50)

Wind speed (m s⁻¹) from the surface elevation z_srf (m) on a regular grid of spacing dx (m): U = u0 + uz max(z, 0)[km] + us |∇z|[m/km], at least 0. The slope is a centred difference over 2n cells, n = max(1, round(L/(2 dx))) for the baseline L = slope_length_km, so that it does not depend on the grid's resolution; one-sided over the cells available at the edges. u_s = 0 needs no dx.

Calibration: ERA5 1981-2010 summer 10-m wind over the ice gives Greenland 2.5 + 1.27 z[km], Antarctica 5.5 + 0.2 z[km] (u_s = 0).

source
Chion.temperature_variability_sigma — Function
temperature_variability_sigma(t_mon, T0; sigma0, slope, smin, smax)

Standard deviation (K) of the daily air temperature about a smooth (monthly-interpolated) daily series, from the monthly mean air temperature t_mon (K): σ = clamp(σ₀ + slope (Tmon − T₀), smin, smax). The daily temperature is then T = Tsmooth + σ ξ, with ξ from red_noise_monthly. σ falls with the monthly mean temperature and is lowest over melting surfaces (Seguinot and Rogozhina 2014, J. Glaciol. 60, 603).

Calibration: ERA5 1981-2010 over the Greenland and Antarctic ice gives σ = 2.0 − 0.14 (T_mon − T₀) in [2, 6] K.

source
Chion.red_noise_monthly — Function
red_noise_monthly(nday, dt_days, nday_mon, tau, seed)

One year of red noise ξ, a value per step of dt_days days (nday ÷ dt_days values): AR(1) with the lag-one correlation exp(−dt/τ), e-folding time tau (days; ERA5: 4-6 d), driven by standard normals; then its mean removed in every month of nday_mon days and the whole scaled to unit variance.

The normals come from a portable Park-Miller minimal standard generator, x ← 16807 x mod (2³¹ − 1) with x₀ = mod(|seed|, 2³¹ − 2) + 1, two uniforms per normal and the Box-Muller cosine branch, so a seed gives the same sequence as the Fortran chion's forcing_red_noise_monthly.
