Running Simulations

A Simulation wraps a model with its forcing years, a spin-up and its output. run! spins the model up, runs every forcing year and writes each output at its own frequency. The model holds its forcing source and reads it one year at a time, so long multi-file records fit in memory, also on a GPU node.

using Chion
using CUDA                        # only for the GPU

forcing = Forcing("/data/MAR/MARv3.14.3-10km-daily-ERA5-{year}.nc"; surface_fluxes=:parameterized)
model = BESSIModel(forcing; backend=CUDABackend())    # CPU() (threads) by default

sim = Simulation(model;
    years=1940:2026,
    spinup=CycledSpinup(1940:1969; cycles=5),
    output=OutputConfig(dir="output/greenland", restart_every=10,
        outputs=[Output("smb_monthly.nc"; variables=:monthly, frequency=:monthly),
                 Output("budget_yearly.csv"; variables=:budget, frequency=:yearly, aggregate=:area_sum)]))
run!(sim)                         # returns sim; the final state is sim.model.state
smbstats(sim)                     # column means (kg m⁻²) and totals (Gt) of the mass fluxes

BESSIModel(forcing; NF, layering, params, backend, state) builds the Grid on the forcing columns; BESSIModel(grid; forcing, …) takes a grid built separately (see Models And Coupling). A GPU backend needs using CUDA first (configuration files run with run_config load it themselves); to_backend(model, CUDABackend()) moves an existing model. BESSIModel(...; state=...) starts from a given host state (e.g. from cpu_state) instead of the initial state of the parameters.

Run directory and restarts

output is an OutputConfig, or one Output or a list of them (written at their paths, without a run directory). With OutputConfig(; dir), the relative paths of the outputs are taken relative to the run directory dir, and the simulation also writes there

  • log.txt: one line per forcing year (column-mean SMB, melt, runoff; wall time),
  • chion_run.toml: the grid, the parameters and the run settings in the format of run_config,
  • restart_<year>.jld2: the state every restart_every years and at the end of the run (restart_every = 0, the default: only at the end). A JLD2 (HDF5) file with the state arrays by name (state/mass, state/temperature, …, layers × columns) and the attributes format_version, model, number_type, columns, chion_version, last_year and next_year; it can also be read with h5py or h5dump.

Simulation(model; years, restart=path) continues from a restart file and skips the spin-up; write_restart(sim, path) writes one at the start of any forcing year. sim.output.outputs lists the outputs of a simulation.

Stepping

run! is resumable: run!(sim; years=1) runs the next forcing year only, and a further run!(sim) continues where it stopped. time_step!(sim) takes one forcing step, finished(sim) tells whether all years are done, and sim.clock holds the position (year index, step, iteration count, time). The outputs are closed when the last year is done.

Forcing

ConstructorUse
Forcing("dir/file_{year}.nc"; …)one NetCDF file per year (missing years are skipped)
Forcing("file.nc"; …)one file of any length; years are sliced from its time axis
Forcing(snowpack_forcing; grid, area)forcing already in memory
Forcing(year -> snowpack_forcing, years; grid, area)a function for preprocessing the loaders do not cover

Keywords of the file constructors:

  • format: :mar for MAR output (variable names, ice mask MSK ≥ 50 %, a constant wind of 5 m s⁻¹, the cell area AREA), :alma for single-site forcing in the ALMA convention of land-surface intercomparisons such as ESM-SnowMIP (Tair, Qair, Psurf, Wind, Rainf, Snowf, SWdown, LWdown in SI units; gaps are filled with the last valid value and the specific humidity becomes relative humidity over ice), :generic for any other file, :auto to detect.
  • surface_fluxes (default :prescribed): :prescribed uses the surface energy fluxes of the file (MAR: net shortwave from SWD − SWU, LWD, SHF, LHF and the albedo AL2; use Params(albedo_scheme = PrescribedAlbedo()) in the model), :parameterized leaves them to Chion, :albedo keeps only the albedo (Chion computes the energy fluxes with it; use PrescribedAlbedo()), :as_loaded keeps whatever the loader provides. With the default :prescribed and a default BESSIModel (dynamic albedo), the MAR fluxes are combined with Chion's own albedo; pass surface_fluxes=:parameterized for a fully parameterised energy balance.
  • variables: names of a generic file, e.g. (air_temperature="t2m", snowfall="sf", rainfall="rf", shortwave_down="ssrd", latitude="lat"); other load_forcing_file keywords (units, defaults) are passed through.
  • files = Dict(year => path) replaces single years; mask = (name, threshold) selects columns; wind is a constant or a variable name; area the column areas (km²) as a vector or variable name, and area_file a separate file that holds it; years restricts the years used; transform = (forcing, year) -> forcing modifies every year (e.g. a temperature change).
  • cache = dir keeps every decoded year in dir as a JLD2 file. A daily MAR year is a compressed NetCDF file of 2.3 GB; decompressing it and selecting the ice columns takes about 3 s, longer than a GPU needs to step the year. The first run writes the cache, later runs (and the later cycles of a spin-up) read a year in about 0.1 s, bitwise identical. A cache file is tied to its source file (path, size, modification time), the loader settings and the version of Chion's loaders, and is rewritten when one of them changes; transform is applied after the cache. Runs may share a directory (about 0.45 GB per Greenland year at 10 km).

forcing_grid(forcing), forcing_years(forcing), forcing_area(forcing) and load_forcing_year(forcing, year) give access to the data, and slice_forcing(f, r) restricts a SnowpackForcing to the time indices r; Grid(forcing) and BESSIModel(forcing; kwargs...) build a grid and a model on the forcing columns. relabel_year(snowpack_forcing, year) moves the time stamps of one year's forcing to another year (the solar geometry stays), for running the weather of base years as future years, e.g. for a delta-method projection.

Spin-up

  • CycledSpinup(years; cycles=5) runs the real forcing years in order, cycles times.
  • ClimatologySpinup(forcing; years=200) repeats another Forcing years times: the whole file of a single-file climatology (e.g. a day-by-day mean year), or the first year of a per-year source. In a configuration file, [spinup] with type = "climatology" and path takes the other settings (format, surface fluxes, …) from [forcing].
  • NoSpinup() (the default) starts from the model's state: the initial state, or the state given to the model constructor (e.g. a restart).

spin_up!(sim) runs the spin-up alone; run! and time_step! call it before the first step. years of the Simulation may repeat years, e.g. repeat(1940:1969, 5), to record every cycle of an equilibrium run.

Outputs

Output(path; variables=:default, frequency=:monthly, aggregate=:columns, kind=:mean,
       period=nothing, regions=nothing, area=nothing, depths=0:0.5:20, snow_cover_threshold=5.0,
       columns=nothing, grid=nothing)
  • path: .nc (NetCDF, CF time axis with period bounds) or .csv (area aggregates or one column).
  • frequency: :step, :daily, :monthly, :yearly, or a period: Hour(3), Day(5), Week(1), Month(6), Year(10). Periods follow the calendar (months from January, days from 1970-01-01). Each record covers one period; its time is the start of the period and time_bnds gives the first and last step.
  • aggregate: :columns (one value per column, on the x–y grid when the grid has coordinates), :area_sum (fluxes and stores in Gt, snow cover in km², firn air content in km³, intensive quantities as area-weighted means) or :area_mean. regions takes a NamedTuple of column masks for several regions.
  • kind: state variables as period means (:mean) or end-of-period values (:snapshot).
  • period = (1980, 2017) writes only those years.
  • columns records only a range of columns (e.g. one member of an ensemble run side by side), with grid their Grid.

NetCDF files from a Simulation use a time dimension with time_bnds. The full model state at every forcing step is Output(path; variables=[:mass, :density, :temperature, …], frequency=:step, kind=:snapshot). available_output_variables(model) lists the variables a model can write. Configuration files

The same simulation as TOML, run with julia --project -m Chion file.toml (Julia ≥ 1.11) or run_config("file.toml"). --backend=gpu and --output-dir=DIR override the file, and --set section.key=value overrides any entry (e.g. --set model.alpha_dry=0.84; in Julia run_config(path; set=["model.alpha_dry" => 0.84])). run_config(path; dry_run=true) returns the Simulation without running it. output_dir is the run directory of the OutputConfig: the outputs, the log, the restarts and a copy of the file (with the overrides applied) are written there.

name = "greenland_parameterized"
backend = "gpu"
years = [1940, 2026]          # first and last year; `repeat = 5` runs them five times
output_dir = "output/greenland"   # the run directory
restart_every = 10            # a restart file every 10 years (0: only at the end)

Published Setups

SimulationGreenlandMARv1(path) and SimulationAntarcticaMARv1(path, climatology) build the Greenland and Antarctic runs of the Chion paper in one call (as Laddie's reproductions): forcing, grid, calibration, spin-up, years and, with dir, the outputs. test/reproductions.jl pins their totals for one MAR year.

sim = SimulationGreenlandMARv1("/data/MAR/MARv3.14.3-10km-daily-ERA5-{year}.nc"; dir = "output/gris",
    files = Dict(2026 => "/data/MAR/MARv3.14.3-10km-daily-ERA5-2026_repaired.nc"))
run!(sim)

Debugging

Simulation(model; debug = DebugConfig(check_nans = true)) checks the state of the active columns for NaN and Inf after every launch of the column step and stops with the variable, column and date.

struct DebugConfig

Debug options of a Simulation.

Set check_nans = true to check the prognostic state of the active columns for NaN and Inf after every launch of the column step (one step when outputs accumulate every step, else up to the next output period). Chion.OutputConfig — Type
struct OutputConfig

Where and what a Simulation writes.

OutputConfig(; dir = nothing, outputs = Output[], log = true, metadata = true, restart_every = 0)

Chion.Forcing — Type
Forcing(path; format=:auto, surface_fluxes=:prescribed, years=nothing, files=Dict(),
        mask=nothing, wind=nothing, area=:auto, transform=nothing, variables=nothing, kwargs...)
  • path: a file, or a pattern with {year} for one file per year (missing years are skipped).
  • format: :mar (MAR daily output: variable names, the ice mask MSK ≥ 50 %, a constant wind of 5 m s⁻¹ and the cell area AREA), :alma (single-site forcing in the ALMA convention of land-surface model intercomparisons such as ESM-SnowMIP: Tair, Qair, Psurf, Wind, Rainf, Snowf, SWdown, LWdown in SI units) or :generic (names from variables and kwargs, as in load_forcing_file). :auto picks :mar when the file has MSK and TTZ/TT, and :alma when it has Tair and Qair.
  • surface_fluxes: :prescribed uses the surface energy fluxes of the file (for MAR the net shortwave from SWD − SWU, LWD, SHF, LHF and the albedo AL2), :parameterized drops them so that Chion computes them, :albedo keeps only the albedo (Chion computes the energy fluxes with it; use with albedo=:prescribed in the model), :as_loaded keeps whatever the loader provides.
  • files: Dict(year => path) overrides single years (e.g. a repaired last year).
  • mask: (name, threshold) selects columns, e.g. ("MSK", 50.0).
  • wind: constant wind speed (m s⁻¹) or the name of a wind variable.
  • area: column areas (km²): :auto (MAR AREA), a variable name, a vector, or nothing.
  • transform: (forcing, year) -> forcing, applied to every year (e.g. a temperature change).
  • variables: NamedTuple of variable names for :generic files, e.g. (air_temperature="t2m", snowfall="sf", rainfall="rf", shortwave_down="ssrd").
  • cache: a directory for decoded forcing years, or nothing. Reading a compressed MAR year (decompression, column selection, unit conversion) takes seconds; with a cache the first run writes every year it loads as a JLD2 file there, and later runs read it back in a fraction of a second, bitwise identical. A cache file belongs to one forcing file (path, size, modification time), the loader settings (format, surface_fluxes, mask, wind, variables, kwargs) and the version of Chion's loaders; when one changes, the year is loaded again and the file replaced. transform is applied after the cache. Runs may share a cache directory.
